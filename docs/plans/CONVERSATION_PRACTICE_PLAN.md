## 3. 持久化与分层方案

- `domain`：意图结果、有效动作、偏好作用范围、目标验证及主问题进度规则。
- `repository`：消息事件、短期状态、已确认事实快照、长期偏好和任务输入快照读写；领域不依赖数据库。
- `service`：提交消息、冻结输入、组装上下文、解释结果校验、动作编排、偏好撤销及事务边界。
- `infrastructure`：在现有 Worker 中运行 intentNode 短图，经 LLMClient 识别；明确动作执行结束后退出。
- 前端 `pages -> features -> api/types`：页面组合布局；feature 管理消息、草稿、任务和简历面板；通用组件不请求业务接口。

初期持久化采用受校验的 JSON 状态及必要关联字段，不拆分大量记忆关系表。跨对话偏好以显式来源关联支持删除清理。消息按稳定顺序和 ID 恢复，重试复用同一提交身份并创建新运行记录。

简历面板和模型上下文都读取对话事实快照。旧数据只能回填可证明的内容，缺失记录给出限制，不伪造历史快照。

## 4. 失败与长链路

消息提交立即返回任务 ID，意图识别及生成在 Worker 中执行；前端沿用轮询。模型失败与“需要澄清”分开，后者是有效业务结果。保存回答成功但反馈失败时保留回答，重试仅执行未完成步骤。

记录节点、模型/提示版本、状态、耗时及允许获取的 token 统计；不得记录密钥。取消和删除集合后禁止 Worker 发布后续结果。偏好和事实写入由业务校验保护，不直接执行模型生成的 SQL 或命令。
