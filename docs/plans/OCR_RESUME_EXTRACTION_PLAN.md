# 阶段一：OCR 简历提取与确认开发计划

状态：已确认，阶段一已实现

## 1. 目标和边界

本计划只实现本地 PDF/DOCX 解析、OCR、证据保存、规则结构化草稿和人工确认表单。上传阶段、解析阶段和确认阶段均不得调用 LLM。问题生成、对话和反馈在下一阶段单独设计。

## 2. 技术路线

```text
React 页面
  -> api/types 契约层
  -> FastAPI controller
  -> Material/ResumeRecognition service
  -> domain 状态与字段规则
  -> repository + SQLite
  -> infrastructure: PyMuPDF / python-docx / RapidOCR / 文件存储
```

- PDF 文本层优先使用 PyMuPDF。
- 无文本层的 PDF 按页调用 RapidOCR 适配器。
- DOCX 提取段落和表格内容，并建立段落序号。
- 结构化草稿由本地解析器和规则生成，不引入模型或外部网络。
- 原始文件和原始 OCR/解析文本不可变；草稿和确认事实分开保存。
- 本阶段不新增 Redis、RabbitMQ 或 Java 服务；当前使用 SQLite 状态和 FastAPI 应用内后台任务执行，后续可在不改变接口契约的情况下替换为队列消费者。

## 3. 顺序阶段

### 阶段 1：需求与契约冻结

- 写入阶段需求文档和本计划。
- 明确 API 只覆盖上传、状态、草稿、重试、确认和证据。
- 为每个状态、字段和证据引用定义测试样例。

交付物：需求文档、计划、PROCESS.md、API 文档同步更新。

### 阶段 2：解析器和证据流水线

- 增加 PDF 文本层解析。
- 增加图片型 PDF 的逐页 OCR。
- 增加 DOCX 段落/表格解析。
- 保存页码、段落号、原文偏移和解析告警。
- 处理单页失败、空页、损坏文件和重试。

交付物：统一解析结果对象、页级证据、材料状态转换和单元测试。

### 阶段 3：本地结构化草稿

- 用本地规则提取个人信息、技能、经历和项目。
- 保留完整技能分类和原始描述。
- 建立字段到证据块的关联和编辑来源。
- 校验字段白名单，禁止写入本阶段之外的固定字段。

交付物：四类模块草稿、证据关联、状态转换和单元测试。

### 阶段 4：后端接口和持久化

- 保持上传接口 `202` 非阻塞。
- 完善识别状态查询、草稿保存、页级重试和模块确认。
- 确认后生成结构化事实证据，未确认草稿不进入事实查询。
- 检查材料版本隔离和删除级联。

交付物：FastAPI 集成测试、API 契约更新和迁移验证。

### 阶段 5：前端材料和确认页面

- 将前端拆成材料库、材料详情和简历确认页面。
- 增加白色简约侧栏、材料上下文栏和页面级状态。
- 实现四个模块表单、证据抽屉、缺失/告警提示、保存和确认。
- 实现状态轮询、局部重试和刷新恢复。

交付物：前端类型/API 层、页面和业务 feature，不允许页面直接调用 `fetch`。

### 阶段 6：门禁验收

- 先通过单元测试。
- 再通过集成测试。
- 由于涉及上传、解析、数据库和前后端页面，必须通过端到端测试。
- 进行文本 PDF、图片 PDF、DOCX、单页 OCR 失败和删除级联人工验收。

## 4. 接口和数据变化

本阶段已落地 `resume_extraction_drafts`、`resume_evidence_links` 和证据表，并通过 Alembic `0002_resume_recognition` 完成迁移；不拆分大量关系表。上传创建 `processing/pending` 状态后立即返回 `202`，本地解析/OCR和规则草稿由应用内后台任务完成，前端通过状态接口轮询。

所有接口继续使用 `/api/v1`、camelCase 和 Problem Details。任何新增字段必须同步更新 `docs/api/rest-contract.md`、前端类型和集成测试。

## 5. 测试矩阵

### 单元测试

- PDF 文本层解析。

- DOCX 段落与表格解析。

- 上传后立即返回 `202`。
- 查询本地解析和识别状态。
- 获取、编辑、刷新恢复草稿。
- 指定页重试只影响目标页。
- 按模块确认和确认全部。

- 删除集合清理原始文件、证据、草稿和关联。

命令：`pytest backend/tests/integration -q`

### 端到端测试

1. 创建材料集合。
2. 上传 PDF/DOCX 简历。
3. 查看本地解析状态。
4. 打开简历确认页。
5. 修改技能或项目字段。
6. 刷新页面并恢复草稿。
7. 只确认技能模块。
8. 查看字段原文证据和页码。
9. 删除材料集合。

命令：`cd frontend; npm run test:e2e`

## 6. 风险和回滚

- OCR 引擎不可用：材料进入 `failed` 或 `partial`，保留原文件并提示安装/重试，不调用远程模型兜底。
- 简历布局复杂：保留原始页图/文本证据，允许用户手动补填，不伪造字段。
- 本地后台任务中断：通过数据库状态识别未完成任务，重启后可重试；不引入外部队列作为本阶段前置依赖。
- 规则识别质量不足：不影响原文证据，用户可以编辑和确认；下一阶段再评估是否为显式用户动作引入 LLM。

本阶段可回滚到已有上传和证据链路，不删除原始材料；新增迁移通过 Alembic 反向迁移或恢复 SQLite 备份处理。
