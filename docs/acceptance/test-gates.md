# 验收门禁

## 层级 1：单元测试

命令：`pytest backend/tests/unit -q`

阶段一覆盖领域规则、DTO 映射、文件安全检查、文本切分（含 DOCX 表格）、PDF/OCR、简历本地结构化识别草稿、PII 本地提取和证据引用；不得依赖或调用 LLM。必须通过。

## 层级 2：集成测试

命令：`pytest backend/tests/integration -q`

阶段一通过 FastAPI 公共 HTTP 接口和临时 SQLite 验证创建集合、后台本地处理状态轮询、上传材料、OCR/解析状态、页级重试、识别草稿保存与确认、修改已确认模块后撤回事实证据、单份材料删除的版本隔离、证据查询和删除级联。对话上下文、补充确认和 LLM 调用属于后续阶段。必须通过。

同时必须验证历史拆分草稿迁移为紧凑结构：技能变为单段 `content` 且不包含项目字段，工作/实习经历和项目移除嵌套项目，项目移除职责、贡献和独立指标字段，工作描述不重复；原始 OCR 证据与已确认事实证据保持不变。

## 层级 3：端到端测试

跨前后端、上传解析、简历识别表单、数据库契约或删除链路的修改必须执行 `npm run test:e2e`。阶段一测试应覆盖浏览器创建集合、上传、查看本地识别草稿、编辑并确认模块、查看原文证据、删除单份材料和删除材料集合；发送问题和确认补充内容属于后续阶段。

识别页还必须验证技能只显示一个完整文本框，经历和项目只显示一个完整描述框，不显示技能标签、嵌套项目或成果指标输入框。

## Agent 追问阶段门禁

Agent 追问属于跨后端、队列、LLM Worker、代码检索和前端的完整功能，完成任何一个相关阶段都不得跳过三层测试。

### 单元测试

必须覆盖：

- 问题范围和问题版本 fingerprint 的稳定性。
- 同一问题/项目版本/提示版本复用参考答案，不重复生成。
- 练习轮次和 `llmRun` 状态转换、幂等和取消规则。
- Pydantic 问题、反馈、参考答案和代码证据快照校验。
- LangChain OpenAI 适配器配置、Fake LLM 测试替身和结构化修复边界。
- 查询计划路径白名单、文件大小、排除目录和命令注入防护。
- `direct`、`inferred`、`insufficient` 三类证据等级。
- 保存回答不调用 LLM；失败任务重试不覆盖旧任务。

### 集成测试

必须通过 FastAPI、临时数据库和测试队列验证：

- 生成问题、保存回答、请求反馈、请求参考答案和继续追问的异步状态。
- `202 + runId`、任务轮询、显式重试和取消。
- Celery Worker 使用测试 LLM Stub，不向真实模型发送请求。
- 参考答案只读取绑定的项目版本，并保存代码路径、行号和快照。
- 无项目绑定、代码证据不足、代码解析失败时的限制提示。
- 问题范围或项目版本变化创建新版本，旧参考答案保持不变。
- 回答版本变化只创建新的反馈输入，不改写原问题版本下的参考答案。
- 材料集合删除级联删除练习轮次、任务、参考答案和代码证据快照。

### 端到端测试

浏览器必须覆盖：

1. 选择问题范围并点击生成问题。
2. 看到排队、运行和完成状态。
3. 保存回答，确认保存动作不触发 LLM。
4. 分别点击反馈、参考答案和继续追问。
5. 查看参考答案、代码引用、证据等级和限制说明。
6. 重复查看同一问题，确认参考答案不变化且不重复创建任务。
7. 修改问题范围，确认生成新问题版本。
8. 失败任务重试、取消和结束练习。

跨组件验收命令仍为：

```powershell
pytest backend/tests/unit -q
pytest backend/tests/integration -q
cd frontend
npm run test:e2e
```

如果使用 Docker 启动 Redis，必须额外验证 Worker 在 Redis 不可用时返回可理解的基础设施错误，不得丢失候选人回答。

本地线程队列和 Celery/Redis 使用同一 HTTP 契约；本阶段已使用 Docker Redis 7 和 Celery worker 完成真实任务消费、状态轮询、结果回写及删除级联验收。真实模型验收必须设置 `LLM_API_KEY`，自动化测试应清空该变量使用确定性演示响应，避免网络和凭据污染测试。

## 文档门禁

接口、领域模型、功能链路或验收行为变化必须同步更新 `AGENTS.md` 索引指向的文档；文档未更新视为未完成。
