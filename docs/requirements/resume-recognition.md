# 简历识别与确认需求

状态：第一版已实现，持续加固

## 1. 目标

候选人上传 PDF 或 DOCX 简历后，系统先抽取可追溯的文本证据，再识别个人信息、技能掌握、工作/实习经历和个人项目，预填到类似招聘网站的表单中。候选人可以修正识别结果；只有确认后的结构化内容才能作为材料集合中的事实证据，供后续面试练习对话使用。

本功能不是从空白开始填写简历，而是“上传简历后的结构化识别和确认”。

## 2. 术语和边界

### 2.1 两阶段处理

OCR 或文档解析负责把页面转换成文本；结构化识别负责把文本归类为简历模块和字段。两阶段必须有独立状态和失败信息，不能把 OCR 失败与字段分类失败混为一谈。

### 2.2 原始内容与结构化内容

- 原始上传文件不可变。
- OCR 文本和页面证据不可变，用于追溯。
- 结构化识别草稿可以编辑、保存和重试。
- 候选人确认后的结构化内容成为材料集合的独立证据，不改写原始文件或 OCR 文本。

### 2.3 本期识别模块

本期只结构化识别以下四类模块：

1. 个人信息
2. 技能掌握
3. 工作/实习经历
4. 项目经验

教育经历、奖项等其他内容保留在原始文本证据中，不进入本期固定字段模型。

## 3. 用户流程

```text
上传 PDF/DOCX
  -> 抽取文本层；必要时逐页 OCR
  -> 保存页级文本证据
  -> 生成结构化识别草稿
  -> 打开识别确认表单
  -> 候选人修改并保存草稿
  -> 按模块确认或全部确认
  -> 生成可用于对话的结构化证据
```

候选人可以在识别失败或结果不完整时手动补全表单。手动补全内容必须标记为候选人编辑内容，并保留对应的确认状态。

## 4. 功能需求

### FR-001 上传和输入类型

- 支持 PDF 和 DOCX 简历。
- 有文本层的 PDF 优先使用文本解析。
- 没有可用文本层的 PDF 使用逐页 OCR。
- 图片型简历必须保留页码对应关系。
- 原始文件进入材料版本后不可覆盖。

### FR-002 独立处理阶段

系统至少区分以下处理状态：

| 层级 | 状态 | 含义 |
|---|---|---|
| 材料 | `processing` | 文件正在解析或 OCR |
| 材料 | `partial` | 部分页面或模块成功，仍有失败内容 |
| 材料 | `ready` | 文本证据可用 |
| 材料 | `failed` | 无法生成可用文本证据 |
| 识别 | `pending` | 等待结构化识别 |
| 识别 | `processing` | 正在生成结构化草稿 |
| 识别 | `awaitingConfirmation` | 草稿已生成，等待候选人确认 |
| 识别 | `confirmed` | 候选人已确认，结构化内容可作为事实证据 |
| 识别 | `failed` | 结构化识别失败，可重试或人工填写 |

OCR 或结构化识别的部分失败不能删除已经成功的页面和字段。
- 远程 LLM 识别不得阻塞上传响应；上传完成后可以先返回 `pending`，由前端轮询识别状态。

### FR-003 个人信息

默认识别以下字段：

- 姓名
- 手机号
- 邮箱
- 所在城市
- 求职方向
- GitHub、博客、个人主页等链接

身份证号、详细住址、出生日期和照片不进入结构化识别字段。

### FR-004 技能掌握

技能模块必须全量识别原简历中的技能描述，而不是只提取少数关键词。例如图片中的以下内容都应被保留在同一个完整文本块中：

- Java 基础
- 后端开发
- 数据库与缓存
- 消息队列
- AI 应用开发
- 开发工具

技能模块保存 `content`、原文证据引用、置信度和候选人编辑标记，不生成技能标签，也不根据技能名称推断熟练度、使用年限和能力等级。

### FR-005 工作和实习经历

工作/实习经历按公司/单位保留记录，但不再使用嵌套项目层级。

父记录字段：

- 公司名称
- 职位名称
- 开始时间
- 结束时间
- 经历类型（工作或实习）
- 完整经历描述
- 原文证据引用

图片中“工作/实习经历”下的项目名称、核心技术、项目背景、实习内容和指标都合并到同一条经历的完整描述中，不生成独立指标字段。

### FR-006 个人项目

个人项目至少保存：

- 项目名称
- 时间范围
- 项目角色
- 核心技术
- 项目描述
- 项目链接
- 原文证据引用
- 可选的 `projectArchiveId`

简历项目与上传的项目档案可以自动提出匹配建议，但名称相似不能直接视为同一项目；存在歧义时必须让候选人确认绑定关系。

### FR-007 识别确认表单

系统提供预填表单页面，至少包含四个可独立编辑的分区：

1. 个人信息
2. 技能掌握
3. 工作/实习经历
4. 项目经验

表单要求：

- 结构化字段可编辑。
- 原始 OCR 文本只读。
- 每个字段或模块可以跳转到对应页码和原文证据。
- 缺失字段显示为空或“未识别”，不能显示模型编造的内容。
- OCR 失败页和低置信度字段必须有明确提示。
- 支持保存草稿、重试识别和确认全部。

### FR-008 草稿和确认

- 识别结果先保存为结构化草稿。
- 草稿自动保存，候选人可以继续修改。
- 候选人可以按四个模块分别确认，也可以执行确认全部。
- 只有确认后的字段才能作为材料集合的事实证据返回给其他对话。
- 未确认草稿可以继续显示在当前表单中，但不能伪装成已确认事实。
- 候选人手动补全的字段必须保留编辑来源和确认状态。

### FR-009 不确定、缺失和冲突

- 无法识别的内容保存为空或待确认状态。
- 简历没有提供的信息不能由模型根据常识补全。
- 多处内容冲突时保留冲突证据，要求候选人选择或修改。
- 可保存置信度，但置信度不能替代候选人确认。
- 需要候选人补充时，可以生成澄清问题；澄清问题不能直接生成事实字段。

### FR-010 重试和新版本

- OCR 失败页面可以单独重试。
- 结构化识别失败可以重新生成草稿，也可以直接人工填写。
- 重新上传或替换简历必须创建新的材料版本和识别草稿。
- 新版本不得覆盖旧版本；已有对话继续绑定原材料版本。

### FR-011 隐私和 LLM 上下文

- 姓名、手机号、邮箱、城市和个人链接默认只在服务端本地保存。
- 发送给 LLM 的上下文默认过滤联系信息，只发送面试训练需要的经历、技能、项目和证据。
- 客户端永远不能取得 LLM API Key。

### FR-012 删除

删除材料集合时必须删除：

- 原始简历
- OCR 和解析文本
- 页级证据
- 结构化识别草稿
- 确认后的结构化证据
- 处理日志
- 绑定的对话、消息和候选人补充内容

删除后不能再通过列表、检索、对话或文件路径访问这些内容。

## 5. 持久化要求

第一版采用混合持久化：

- `materials`：原始文件和解析状态。
- `evidence_chunks`：页级或段落级原始证据。
- `resume_extraction_drafts`：结构化识别草稿 JSON、状态、模型版本和更新时间。
- `resume_evidence_links`：结构化字段到证据块、页码和偏移的关联。
- 本地数据目录：原始文件、OCR 中间产物和诊断日志。

结构化识别结果暂时保留完整 JSON；只有需要筛选、检索或统计的字段才拆成关系表。所有数据都必须绑定不可变的 `materialRevisionId`。

## 6. 接口需求（第一版已实现）

以下是需求阶段的资源建议，实现时必须同步更新 `docs/api/rest-contract.md` 和前后端类型：

- `GET /api/v1/materials/{materialId}/recognition`：获取识别状态和草稿。
- `PATCH /api/v1/materials/{materialId}/recognition`：保存候选人编辑后的草稿。
- `POST /api/v1/materials/{materialId}/recognition/retry`：重试 OCR 或结构化识别。
- `POST /api/v1/materials/{materialId}/recognition/confirm`：按模块或全部确认。

JSON 使用 camelCase；错误响应使用 Problem Details，并包含稳定的 `code`。

已实现的补充约束：修改已确认模块会撤销该模块的事实证据；PDF 支持按页 OCR 重试，DOCX 页码重试会返回明确告警并执行整份解析。

## 7. 非功能需求

- 任何上传的项目代码只允许静态读取，不能执行、构建或测试。
- OCR、结构化识别和人工编辑必须可追溯到材料版本。
- 识别失败不能导致原始文件和已成功证据丢失。
- Docker 可以作为可选开发环境；没有 Docker 时，本地 Python + SQLite 流程仍必须可运行。
- 所有跨前后端、上传、数据库契约和删除链路的修改必须通过端到端测试。

## 8. 验收标准

### 自动化验收

1. 文本型 PDF、图片型 PDF 和 DOCX 都能进入统一流程。
2. 四类模块字段均能定位到页码或原文证据。
3. OCR 部分失败时，成功页面仍可编辑和确认。
4. 表单编辑不会修改原始文件和 OCR 原文。
5. 未确认内容不会作为事实证据被其他对话使用。
6. 新版本不会改变旧对话绑定的材料版本。
7. 删除材料集合会清理全部原始和派生数据。

### 人工验收

1. 上传一份包含“技能掌握、工作/实习经历、项目经验”的简历。
2. 检查技能完整描述出现在单个文本框中，不出现技能标签卡片。
3. 检查工作/实习经历和项目经验各按记录显示一个完整描述框，不出现嵌套项目或成果指标输入框。
4. 修改一个识别错误字段并刷新页面，确认草稿仍然存在。
5. 只确认技能模块，确认其他模块仍处于待确认状态。
6. 创建对话，确认只有已确认内容被当作事实证据。
7. 删除材料集合，确认文件、数据库记录和对话都无法访问。

## 9. 明确不在本需求内

- 从空白页面创建一份新简历。
- 自动补写候选人没有提供的经历、指标或技术细节。
- 自动判断技能真实熟练度。
- 在线多人协作和云端文件存储。
- 执行、构建、测试或修改上传的项目代码。
